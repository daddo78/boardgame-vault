Board Game Curator

From a garage shelf tracker to a curator for friends

Sixteen days, three homes for the data, one near-total wipe, and a curator named Nathan. This is how a page for tracking one shelf became an invite-only site where friends share their collections, log their plays, and an AI curator reads their rulebooks.

Started as · Oct 11
  • A web page to track one shelf
  • Two-way sync with BoardGameGeek, planned
  • n8n as the database
  • Cover art found by an AI agent
Became · Oct 26
  • An invite-only site: every member has a shelf, Dan's an ordinary one among them, and friends connect by code
  • Nathan, an AI curator who remembers you, reads photos, cites rulebook pages, and streams his answers
  • Postgres for the data, one small API and its jobs worker for the logic, all on one VPS
  • A 1,684-game catalog with BoardGameGeek box art
  • Plays logged on any device, your stats as a story, and two-way sync with your own BoardGameGeek account: the plan from day one, done

The path

How it got here

Red spaces are the setbacks. Dates are from git commits, server logs and API responses.

Genesis · Oct 11
  1. Oct 11 · evening

    The spark

    "I'm creating a web page for my board game collection. I want it to connect to BoardGameGeek and keep a database on n8n." A dark-themed "Vault" prototype goes up the same evening on GitHub Pages at bg.ondorilabo.com.

  2. Oct 11

    BGG hits a wall

    Every BoardGameGeek API call comes back 401. Their API now requires a registered app and an approved token, about a week's wait with no guarantee. BGG is set aside, not patched around.

    3 workflows unpublished, kept for later
  3. Oct 11

    Teaching an agent not to make things up

    Asking a model for a cover-art URL gets confident, broken links. The fix: the model finds a real product page, then plain code reads that page's own og:image tag and checks it's really an image.

    25% → 68% of covers found
  4. Oct 11

    Everyday use

    Delete with a confirmation, thumbnails twice as big, and a real phone layout. The page starts to feel like something to use every day.

Identity and scale · Oct 11–12
  1. Oct 11–12

    Finding a face

    Dan's own navy-and-gold garage logo arrives, and the page's palette, type and header are rebuilt around it as Game Garage Collection.

  2. Oct 12

    The real shelf

    A 260-row spreadsheet of the actual collection is reconciled against what's live: 112 games updated, 104 added. For the first time the page matches the shelf.

    216 games, numbered 1–216
  3. Oct 12

    An icon for every game

    Each game gets an icon picked by AI from the real 5,200-icon Tabler catalog and checked against it, so nothing renders broken. Sharper prompts push the generic meeple fallback down.

    33% → 23% → 5.5% → 4% fallback
Crisis and resilience · Oct 17–18
  1. Oct 17

    The tunnel falls over

    n8n goes dark with Cloudflare Tunnel error 1033. The tunnel ran on a home connection, and Docker gave n8n a new random port on every restart.

  2. Oct 17

    Moving house

    n8n and its own tunnel are rebuilt together on a Hostinger VPS, on one Docker network with no ports open to the internet. The home connection is out of the loop.

  3. Oct 17

    Lost, and found

    A VPS restore wipes n8n's workflows and data. All 216 games are rebuilt from migration files still on disk and reseeded into a new Airtable base within the hour.

    0 games lost
  4. Oct 18 · morning

    Locking the doors

    Every change now needs a Google sign-in, and only a server-confirmed owner sees the editing controls. A working BGG token finally arrives, for ratings and checking titles.

Meet Nathan · Oct 18
  1. Oct 18 · 11:30

    Ask becomes Ask Nathan

    A question box that knows who's playing, their ratings and their play history picks games with reasons. Within half an hour it has a name: Nathan, the collection's curator.

  2. Oct 18 · afternoon

    Board Game Curator

    The site is renamed around him: an illustrated hero of Nathan with his magnifying glass, the red comic title, and the line "Your collection cataloged and cultivated with love." The search bar becomes his Ask bar, and his answers read like an AI overview that filters the shelf.

  3. Oct 18 · evening

    A real database

    Airtable lasts a day. Postgres moves in beside n8n on the server, with NocoDB as a spreadsheet view and a nightly backup to a private GitHub repo. By 10 pm the live site runs on it.

    Third home for the data in 8 days
  4. Oct 18 · late

    Friends get shelves

    Friends get their own shelves imported from BoardGameGeek, and visitors see a welcome page. The collection, people and Nathan become members-only.

A site for friends · Oct 19
  1. Oct 19 · morning

    Faster, watched, and fair

    Failure alerts email Dan when a workflow breaks or a backup stalls. Turning off the models' thinking speeds Nathan up. Each member gets 30 questions a day, with a quiet counter.

    10.7 s → 6.4 s per answer
  2. Oct 19

    Friend codes

    Enter a friend's code and you're connected. @mention a friend and Nathan knows their taste and plays. Your own shelf is home; a friend's opens view-only.

  3. Oct 19 · night

    Your shelf is what you own

    BGG brings in plays only, never games. Add games by name (pick several at once), by photo, or from a spreadsheet. Nathan learns facts about any game, "would I like it?", and what to buy next.

Nathan grows up · Oct 20
  1. Oct 20 · afternoon

    Profiles, wishlists, Top 10s

    Profile pages, a Top 10 of all time, and wishlists friends can see as gift ideas. Nathan gets social: "what can we play at Keith's?", "who has a co-op for 2?", "which friends would love Brass?"

  2. Oct 20 · evening

    Tests, dashboard, release notes

    A demo member with 150 games and about 960 plays to test against. Database checks on every deploy, a nightly self-test, an admin dashboard, and release notes posted to the testers' Discord.

    31 checks and 18 questions on day one
  3. Oct 20 · late

    Nathan gets to know you

    Chats are saved, and he keeps short notes ("only has an hour on weeknights", "stop suggesting Cascadia") with an "I'll remember…" line under his answer. He stops repeating himself by remembering two weeks of picks. Members see and delete what he remembers.

Reading the rules · Oct 21
  1. Oct 21 · 7:25

    Double emails, jumping popups

    A mail server's "try again" reply made the nightly report arrive twice, so email retries come out. On phones, scrolling a popup scrolled the shelf behind it; popups now hold the page still.

  2. Oct 21 · morning

    Everyone's plays, every night

    Every member's BoardGameGeek plays (and what BG Stats posts there) sync at 4:30 am, or now with "Sync my plays". What's new moves into the cog, read straight from the release notes.

  3. Oct 21 · 10:21

    Rulebooks, with page numbers

    Docling ran out of memory on the server, so a vision model reads each rulebook page by page instead, icons and sidebars included. The PDF is deleted after; the text and a link to the official copy stay. Nathan answers "(Rulebook, p. 16)" for anyone, whatever edition they own.

    SETI, Andromeda's Edge + appendix, Fate of the Fellowship
  4. Oct 21 · late morning

    Show Nathan a photo

    Snap an icon and ask what it means, and he finds it in the rulebook. Snap a box, a board, or just the components on the table, and he names the game. Plus full-screen chat and a back-to-top button.

  5. Oct 21 · afternoon

    An admin portal and a costs page

    Invites now send a welcome email. Dashboard, members, Nathan's settings and every rulebook move into one admin portal, with a Costs page that reads exact AI spending from OpenRouter every hour.

    52 database checks
  6. Oct 21 · evening

    Box art for everything, instant search

    A background job fills in every catalog game that never got its BGG details, 20 every 10 minutes. Typing a game's name finds it on your shelf instantly. Admins upload rulebooks for any game, and a Cloudflare token makes each update live within minutes.

    455 games without art → 7
  7. Oct 21 · night

    Feedback, from the cog

    Members send feedback with a face for how it's going; Dan gets an email he can reply to, and Admin → Feedback keeps the list. Expansions open on BGG and can be removed, "thinning" becomes "culling", and the page stops jumping sideways when a popup opens.

    57 database checks
  8. Oct 22

    Nathan gets his own service

    A small API (api.ondorilabo.com) goes up beside n8n: one sign-in check for everything, and deploys that never take the site down. Nathan moves in that evening, his steps copied word for word from n8n so the two can't drift, and his words now appear as he writes them, with a Stop button.

    first words in ~2.2 s, 25/25 questions
  9. Oct 23 · morning

    Nathan for everyone, sooner

    The new Nathan goes on for everyone. He starts reading the question on just the names at the table while the rest of the shelf loads, and his first words arrive half a second sooner. Full answers come in about 4.8 seconds, at the same cost.

    2.6 s → 2.2 s to first words
  10. Oct 23 · afternoon

    The site moves over

    Everything the page reads, then the everyday changes (stars, shelves, friends, wishlists, profiles, BGG search, feedback, invites) move to the API, each area behind its own switch in Admin and checked against n8n before it goes on. Email now goes out from the API too.

    14 switches, all on
  11. Oct 23 · afternoon

    Nathan asks back

    "What should I play with my kids?" is never a solo game any more, leaves out the teen games and ends with "How old are your kids?". Rulebooks name themselves from their first pages ("The Norwegians"), "Expansion rulebook" is a type, and only admins change or remove rulebooks.

    27/27 questions
  12. Oct 23 · evening

    Faster people, tested memory

    The people on a shelf load about three times faster, and much faster on a big shelf. New tests check that Nathan remembers what you tell him, and turned up two misses, both fixed. Signing in is now one click on Google's own "Continue as" chooser.

    a big shelf's people: 3.9 s → 1.2 s
One service, one shelf · Oct 24–25
  1. Oct 24 · overnight

    Everything leaves n8n

    Dan went to bed and said "do it all while I sleep." By morning the scheduled jobs (nightly play syncs, the self-test, the backup check, Fill Catalog, cost readings), the rulebook reader, photos, CSV and play imports and the failure emails all run in a second copy of the API, the jobs worker, with every run written to the database. n8n's nine schedules were switched off; its webhooks stay only as a fallback.

    11 jobs · 70 API tests · 65 database checks
  2. Oct 24

    A look around the server

    The spreadsheet view (NocoDB) had been restarting all night, out of memory; it got more room. A walk through every process on the server found an old automation container to clean out and a remote-desktop relay (RustDesk) that would accept anyone; it now takes only clients holding its key. Access to the server is by key, as a non-root user.

    one open relay closed · root password due for a change
  3. Oct 25 · morning

    Dan's shelf is an ordinary shelf

    "Why is my collection treated differently?" It had its own routes and its own adapter dating from the Airtable days. Now Dan adds, edits, removes and syncs through the same routes and the same database functions as everyone, and any game new to the catalog gets its blurb and icon the way only his used to. Only the visibility rule still tells his shelf apart. The last of the Airtable-era write code is gone.

    4 routes and 3 modules removed · 213 games, every count intact
  4. Oct 25 · morning

    The same site for everyone

    Dan's rule, said plainly: features are the same for him and for members; only admin vs member differs. So "Sync my plays" lives in the Settings cog for everyone and asks for your BGG username the first time, the Players screen is for admins (not just the owner), members can finally tap the stars on their own cards and see the 📖 rulebook markers, and plays logged from the site tell BG Stats they came from Board Game Curator.

    v0.22 · 76 checks, 74 tests

Attached · the current architecture

How it runs today

A static page talks to one small API on one small server; Nathan lives there and streams his answers. A second copy of the same code, the jobs worker, runs the scheduled jobs and the long ones (play syncs, the self-test, reading rulebooks, imports). Both read and write one Postgres database and call Google, BoardGameGeek and AI models; for members who link their BGG account, the worker sends their plays, shelf and stars there every two minutes. n8n idles beside them as a fallback.

How Nathan answers a question

In the API, with his words appearing as he writes: first words in about 2 seconds, the whole answer in about 5.

  1. DatabaseCount and remember. Uses one of the member's 30 daily questions, then loads what Nathan knows about them, his picks for them in the last two weeks, and this chat so far.
  2. GeminiUnderstand. Turns the question (and any photo) into a plan: what kind of question, who's playing, player count, time, weight, games named. It starts on who's at the table while the rest of the shelf loads.
  3. CodeFirm rules. "A game I don't own" means ideas to buy, "my" means the asker's shelf, "who has…" looks across friends' shelves, "with my kids" is never a solo game.
  4. DatabaseLook things up. Finds games even from partial or misspelled names, who owns them, friends' shelves, Top 10s, wishlists, and for rules questions the best-matching rulebook sections with their pages.
  5. BGGFill the gaps. A game that isn't in the catalog yet comes from BoardGameGeek.
  6. CodeShortlist. Hard limits first, then scores by the group's ratings, plays, taste, and how good the game is at this player count.
  7. ClaudeNathan writes the answer from the shortlist only, in his voice, citing rulebook pages; notes anything lasting the asker told him; and asks one short question back when a missing fact would change his pick.
  8. CodeCheck and save. Drops any game that wasn't on the shortlist, saves the turn and what he learned, and logs the question's kind, time and cost (never its words).

How a change ships

  • Edit the page, the API and its jobs (server/bgc-api), or a numbered SQL file, and try it on the test site (bg-dev) as Nathan, the test member.
  • Apply database changes with apply.sh; each file is safe to run again, and a ledger remembers which have run.
  • The API's deploy.sh runs its 93 tests, builds, swaps in the new version only once it's healthy, then recreates the jobs worker from the same image; a trial build answers Nathan's 37 test questions first.
  • The 176 database checks run on every deploy and every night; any failure stops the deploy or emails Dan.
  • A new area of the site starts Off in Admin, then Admins only, then Everyone.
  • Back up the live database, then git push to GitHub Pages, then clear Cloudflare's cache so it's live in a minute or two.
  • Post the version's notes to the testers' Discord, only when Dan says so.

The roadmap · planned for October 25, done by the 25th; BGG both ways by the 26th

Nathan's own service, and what's left

Most of the n8n workflows were really small web endpoints. The usual way to build that is one small service: one sign-in check for every request, one deploy, one place to look when something breaks. Nathan moved first, because it's the change members feel. The scheduled jobs went last, overnight on the 24th, into a worker built from the same code.

Phase 1 · done Oct 22

The service

  • A small TypeScript service (Hono on Node) in Docker on the same server, at api.ondorilabo.com. No new hosting cost
  • Every request checks the Google sign-in and membership in one place, with Google's keys cached (no call to Google each time)
  • Inputs checked, plain error messages, per-member limits, and only our site can call it
  • Updates go out without the site blinking: 43 of 43 health checks answered during a handover
Phase 2 · done Oct 23

Nathan moves in

  • Answers stream: first words in about 2.2 seconds, the whole answer in about 4.8 (was a 6-second wait)
  • His steps are n8n's own code, copied word for word, so the two can't drift apart
  • Stop, “Ask again”, and a half-written answer is kept
  • 25 of 25 test questions, at the same cost per question
Phase 3 · done Oct 23

Everything else

  • Everything the page reads, and the everyday changes (stars, shelves, friends, wishlists, profiles, BGG search, feedback, invites), moved behind switches in Admin, each checked against n8n first
  • Email goes out from the API through Resend
  • Dropped after measuring: one combined request on page load. The page already asks for its parts at once, so it waits only for the slowest; fixing that one (people) made it about 3× faster instead
Phase 4 · done Oct 24–25

The jobs, and one shelf

  • A jobs worker from the same code: nightly syncs, Fill Catalog, the rulebook reader, cost readings, the backup check, the self-test and failure emails, each run logged
  • Photos, CSV and play imports and rulebook uploads moved to the API, the long parts handed to the worker
  • Dan's own collection became an ordinary shelf on the same routes; the Airtable-era adapter's write side is gone
