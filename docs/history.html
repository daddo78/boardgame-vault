Board Game Curator

From a garage shelf tracker to a curator for friends

Eleven days, three homes for the data, one near-total wipe, and a curator named Nathan. This is how a page for tracking one shelf became an invite-only site where friends share their collections and an AI curator reads their rulebooks.

  • A web page to track one shelf
  • Two-way sync with BoardGameGeek, planned
  • n8n as the database
  • Cover art found by an AI agent

  • Nathan, an AI curator who remembers you, reads photos, and cites rulebook pages
  • Postgres for the data, 53 n8n workflows for the logic, all on one VPS
  • A 1,685-game catalog with BoardGameGeek box art, and plays synced nightly

The path

How it got here

Red spaces are the setbacks. Dates are from git commits, server logs and API responses.

Genesis · Oct 11
  1. Oct 11 · evening

    The spark

    "I'm creating a web page for my board game collection. I want it to connect to BoardGameGeek and keep a database on n8n." A dark-themed "Vault" prototype goes up the same evening on GitHub Pages at bg.ondorilabo.com.

  2. Oct 11

    BGG hits a wall

    Every BoardGameGeek API call comes back 401. Their API now requires a registered app and an approved token, about a week's wait with no guarantee. BGG is set aside, not patched around.

    3 workflows unpublished, kept for later
  3. Oct 11

    Teaching an agent not to make things up

    Asking a model for a cover-art URL gets confident, broken links. The fix: the model finds a real product page, then plain code reads that page's own og:image tag and checks it's really an image.

    25% → 68% of covers found
  4. Oct 11

    Everyday use

    Delete with a confirmation, thumbnails twice as big, and a real phone layout. The page starts to feel like something to use every day.

Identity and scale · Oct 11–12
  1. Oct 11–12

    Finding a face

    Dan's own navy-and-gold garage logo arrives, and the page's palette, type and header are rebuilt around it as Game Garage Collection.

  2. Oct 12

    The real shelf

    A 260-row spreadsheet of the actual collection is reconciled against what's live: 112 games updated, 104 added. For the first time the page matches the shelf.

    216 games, numbered 1–216
  3. Oct 12

    An icon for every game

    Each game gets an icon picked by AI from the real 5,200-icon Tabler catalog and checked against it, so nothing renders broken. Sharper prompts push the generic meeple fallback down.

    33% → 23% → 5.5% → 4% fallback
Crisis and resilience · Oct 17–18
  1. Oct 17

    The tunnel falls over

    n8n goes dark with Cloudflare Tunnel error 1033. The tunnel ran on a home connection, and Docker gave n8n a new random port on every restart.

  2. Oct 17

    Moving house

    n8n and its own tunnel are rebuilt together on a Hostinger VPS, on one Docker network with no ports open to the internet. The home connection is out of the loop.

  3. Oct 17

    Lost, and found

    A VPS restore wipes n8n's workflows and data. All 216 games are rebuilt from migration files still on disk and reseeded into a new Airtable base within the hour.

    0 games lost
  4. Oct 18 · morning

    Locking the doors

    Every change now needs a Google sign-in, and only a server-confirmed owner sees the editing controls. A working BGG token finally arrives, for ratings and checking titles.

Meet Nathan · Oct 18 New since the first write-up
  1. Oct 18 · 11:30

    Ask becomes Ask Nathan

    A question box that knows who's playing, their ratings and their play history picks games with reasons. Within half an hour it has a name: Nathan, the collection's curator.

  2. Oct 18 · afternoon

    Board Game Curator

    The site is renamed around him: an illustrated hero of Nathan with his magnifying glass, the red comic title, and the line "Your collection cataloged and cultivated with love." The search bar becomes his Ask bar, and his answers read like an AI overview that filters the shelf.

  3. Oct 18 · evening

    A real database

    Airtable lasts a day. Postgres moves in beside n8n on the server, with NocoDB as a spreadsheet view and a nightly backup to a private GitHub repo. By 10 pm the live site runs on it.

    Third home for the data in 8 days
  4. Oct 18 · late

    Friends get shelves

    Friends get their own shelves imported from BoardGameGeek, and visitors see a welcome page. The collection, people and Nathan become members-only.

A site for friends · Oct 19 New
  1. Oct 19 · morning

    Faster, watched, and fair

    Failure alerts email Dan when a workflow breaks or a backup stalls. Turning off the models' thinking speeds Nathan up. Each member gets 30 questions a day, with a quiet counter.

    10.7 s → 6.4 s per answer
  2. Oct 19

    Friend codes

    Enter a friend's code and you're connected. @mention a friend and Nathan knows their taste and plays. Your own shelf is home; a friend's opens view-only.

  3. Oct 19 · night

    Your shelf is what you own

    BGG brings in plays only, never games. Add games by name (pick several at once), by photo, or from a spreadsheet. Nathan learns facts about any game, "would I like it?", and what to buy next.

Nathan grows up · Oct 20 New
  1. Oct 20 · afternoon

    Profiles, wishlists, Top 10s

    Profile pages, a Top 10 of all time, and wishlists friends can see as gift ideas. Nathan gets social: "what can we play at Keith's?", "who has a co-op for 2?", "which friends would love Brass?"

  2. Oct 20 · evening

    Tests, dashboard, release notes

    A demo member with 150 games and about 960 plays to test against. Database checks on every deploy, a nightly self-test, an admin dashboard, and release notes posted to the testers' Discord.

    31 checks and 18 questions on day one
  3. Oct 20 · late

    Nathan gets to know you

    Chats are saved, and he keeps short notes ("only has an hour on weeknights", "stop suggesting Cascadia") with an "I'll remember…" line under his answer. He stops repeating himself by remembering two weeks of picks. Members see and delete what he remembers.

Reading the rules · Oct 21 New
  1. Oct 21 · 7:25

    Double emails, jumping popups

    A mail server's "try again" reply made the nightly report arrive twice, so email retries come out. On phones, scrolling a popup scrolled the shelf behind it; popups now hold the page still.

  2. Oct 21 · morning

    Everyone's plays, every night

    Every member's BoardGameGeek plays (and what BG Stats posts there) sync at 4:30 am, or now with "Sync my plays". What's new moves into the cog, read straight from the release notes.

  3. Oct 21 · 10:21

    Rulebooks, with page numbers

    Docling ran out of memory on the server, so a vision model reads each rulebook page by page instead, icons and sidebars included. The PDF is deleted after; the text and a link to the official copy stay. Nathan answers "(Rulebook, p. 16)" for anyone, whatever edition they own.

    SETI, Andromeda's Edge + appendix, Fate of the Fellowship
  4. Oct 21 · late morning

    Show Nathan a photo

    Snap an icon and ask what it means, and he finds it in the rulebook. Snap a box, a board, or just the components on the table, and he names the game. Plus full-screen chat and a back-to-top button.

  5. Oct 21 · afternoon

    An admin portal and a costs page

    Invites now send a welcome email. Dashboard, members, Nathan's settings and every rulebook move into one admin portal, with a Costs page that reads exact AI spending from OpenRouter every hour.

    52 database checks
  6. Oct 21 · evening

    Box art for everything, instant search

    A background job fills in every catalog game that never got its BGG details, 20 every 10 minutes. Typing a game's name finds it on your shelf instantly. Admins upload rulebooks for any game, and a Cloudflare token makes each update live within minutes.

    455 games without art → 7

Attached · the current architecture

How it runs today

A static page talks to 53 n8n workflows on one small server. The workflows read and write one Postgres database and call Google, BoardGameGeek and AI models. Nathan is one of those workflows.

How Nathan answers a question

  1. DatabaseCount and remember. Uses one of the member's 30 daily questions, then loads what Nathan knows about them, his picks for them in the last two weeks, and this chat so far.
  2. GeminiUnderstand. Turns the question (and any photo) into a plan: what kind of question, who's playing, player count, time, weight, games named.
  3. CodeFirm rules. "A game I don't own" means ideas to buy, "my" means the asker's shelf, "who has…" looks across friends' shelves.
  4. DatabaseLook things up. Finds games even from partial or misspelled names, who owns them, friends' shelves, Top 10s, wishlists, and for rules questions the best-matching rulebook sections with their pages.
  5. BGGFill the gaps. A game that isn't in the catalog yet comes from BoardGameGeek.
  6. CodeShortlist. Hard limits first, then scores by the group's ratings, plays, taste, and how good the game is at this player count.
  7. ClaudeNathan writes the answer from the shortlist only, in his voice, citing rulebook pages, and notes anything worth remembering about the asker.
  8. CodeCheck and save. Drops any game that wasn't on the shortlist, saves the turn and what he learned, and logs the question's kind, time and cost (never its words).

How a change ships

  • Edit the page, n8n/gen.js, or a numbered SQL file.
  • Apply database changes; each file is safe to run again.
  • deploy.sh generates and publishes the workflows, restarts n8n, and fails if any of the 52 checks fail.
  • git push to GitHub Pages, then clear Cloudflare's cache so it's live in a minute or two.
  • Post the version's notes to the testers' Discord, only when Dan says so.

The roadmap · starting Sunday, October 25

What's next: Nathan's own service

Most of the 53 n8n workflows are really small web endpoints. The usual way to build that is one small service: one sign-in check for every request, one deploy, one place to look when something breaks. Nathan moves first, because it's the change members will feel: his answers start appearing in about a second instead of after six. n8n keeps the scheduled jobs it's good at.

Phase 1 · the foundation

The service

  • A small TypeScript service in Docker on the same server, beside the database. No new hosting cost
  • Every request checks the Google sign-in and membership the same way, in one place
  • Inputs checked, plain error messages, per-member limits, and only our site can call it
  • The same database functions as today, so what members can see doesn’t change
  • Updates go out without the site blinking: the new version starts and proves it’s healthy before taking over
Phase 2 · the big one

Nathan moves in

  • Answers stream: his first words in about a second, the rest appearing as he writes
  • A Stop button while he writes, Retry if something fails, and a half-written answer is kept
  • The 24 test questions run in seconds, old and new side by side on the same questions
  • Admins try him first, then everyone; if the new service is ever down, the page quietly uses the old one
  • Done when: first words under 1.5 s, full answers no slower than today, 24 of 24 tests, no higher cost
Phase 3 · after Nathan

Everything else

  • About 30 small endpoints (shelf, ratings, wishlist, friends, profile, rulebooks, feedback, admin) become routes in the service
  • The page loads with one request instead of several, so your shelf appears faster
  • Each area switches over only once its checks pass; the old version is retired a week later
Phase 4 · no change

What stays in n8n

  • Nightly play sync, Fill Catalog, the rulebook reader, cost readings, the backup check and failure alerts
  • Scheduled background work is what n8n does best, with a history of every run to look back on
