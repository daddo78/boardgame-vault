# Production History

**Scope of this document:** the project's origin (Oct 11, 2026) through Oct 23, 2026. The first part, through Oct 18, was written by the session that built the early version and handed it off; it is kept as written. **"After the handoff"** continues the story from git history, ROADMAP.md and the session that did the Oct 22–23 work. For current architecture and features, **README.md, ROADMAP.md and `docs/architecture.html` are the source of truth, not this file.** Treat this document as the story of how it got here and why, not as a description of what's running today.

No claim below is invented. Dates and times are from observed git commit timestamps, server logs, database queries and API responses; anything estimated is labeled as such. The early part uses UTC; "After the handoff" gives dates and parts of the day (Eastern), because its commits were made from machines in different time zones.

---

## Origin

Oct 11, 2026. The request: a web page to track a personal board game collection, syncing with BoardGameGeek (BGG), backed by n8n as the database. Built as a static `index.html` (no build step), pushed to `daddo78/boardgame-vault` on GitHub, hosted on GitHub Pages at a custom domain (`bg.ondorilabo.com` via Cloudflare DNS).

## Timeline

**Oct 11, 21:54 UTC — Initial commit.** Dark-themed prototype ("Vault"), n8n workflows for the collection CRUD, GitHub Pages + custom domain live within the hour.

**Oct 11, ~22:30 UTC — BGG blocked.** Every BGG XML API call returns 401. BGG's policy now requires a registered application and an approved Bearer token (roughly a week's turnaround, no guarantee of approval). Decision: drop BGG entirely rather than ship three permanently-broken workflows. The three BGG-dependent workflows were unpublished, not deleted, in case a token arrived later (it did, see below).

**Oct 11, 23:00–23:30 UTC — AI cover-art agent, and a hallucination lesson.** First attempt: ask an LLM for a cover-art image URL directly. It hallucinates plausible-but-404 URLs even when explicitly told not to guess. Fix, and the pattern worth reusing anywhere an LLM is asked to produce a URL: (1) have the model find and return a *source webpage* it actually saw in search results, never a guessed URL; (2) deterministically fetch that page's own HTML and regex-extract its `og:image` meta tag — no LLM in this step; (3) validate the extracted URL actually returns `image/*` before saving. Preferring GameNerdz product pages in the prompt raised the hit rate from ~25% to ~68%.

**Oct 11, 23:29 – Oct 12, 00:17 UTC — Feature pass + rebrand.** Delete with confirmation modal, 2x thumbnails, mobile layout. Then a full rebrand around user-supplied logo artwork (navy/gold palette, Fredoka + Outfit fonts, Font Awesome icons, later swapped to Tabler Icons).

**Oct 12, ~00:34 UTC — Full collection merge.** User supplied a 260-item CSV of their real collection. Reconciled against the live 112-game table: 112 updated, 104 inserted. Final count: 216 games, numbered 1–216, matching the physical shelf for the first time. One real incident during this period: browser-automation testing of the delete button accidentally deleted 2 real games (Citadels, The Castles of Burgundy); caught via a row-count audit, disclosed to the user, and restored from data still held in context.

**Continuing, same session — Icon system.** User asked for each game to show an AI-picked icon representing it, rather than a cover photo. Built: fetch the *live* Tabler Icons catalog (~5,200 names) at workflow run time, have an LLM pick per-game, validate the pick against the live-fetched catalog before saving (same anti-hallucination discipline as the cover-art agent — never trust a generated identifier without checking it against ground truth). Iterated the prompt over several passes, bringing the generic `meeple` fallback rate down: 33% → 23% → 5.5% → 4%.

**Oct 12 – Oct 17 — idle.** No activity; the user was away from the project for 5 days.

**Oct 17, 13:42 UTC — Infrastructure failure.** `n8n.ondorilabo.com` down, Cloudflare Tunnel error 1033. Root cause: `cloudflared` ran on the user's home network (unreliable connection), and n8n's Docker container had no fixed host port (`ports: - "5678"` in compose, which Docker interprets as "assign a random host port on every start") — so even when the tunnel reconnected, its cached target port was stale.

**Oct 17, ~14:00–17:00 UTC — Migration to Hostinger.** n8n and a newly-created, dedicated Cloudflare Tunnel were rebuilt to run together in one Docker Compose stack on the Hostinger VPS (`148.230.83.130`), sharing a Docker network so n8n needs zero host ports exposed to the internet. A **separate** tunnel was used deliberately: the user's existing tunnel also carried 11 unrelated home-lab services (Sonarr, Radarr, Nextcloud, etc.) on the same home connection, and Cloudflare Tunnel replicas are tunnel-wide, not per-route — reusing it risked those services breaking unpredictably.

**Oct 17, afternoon — Decision to migrate off n8n's Data Table.** With the infrastructure fragility exposed, and given this conversation's root cause was in part "the collection's availability depends on n8n," the call was made to move the actual data store to Airtable, keeping n8n for automation/workflow logic only. All 216 games were seeded into a new Airtable base ("Board Game Garage Collection", table "Games").

**Oct 17, evening — Data wipe and recovery.** A Hostinger VPS restore (run by the user, intending to fix something unrelated) wiped n8n's workflows and its internal database outright — including the original Data Table, by then already superseded by Airtable but still a loss of the live n8n workflow definitions. Recovery: the original CSV-merge intermediate files (`current_collection.json`, `final_insert_rows.json`) were still present on local disk from the Oct 12 migration work and were used to reconstruct and reseed all 216 games into Airtable. Zero games were permanently lost.

**Oct 17 — BGG token obtained; handoff to a new session.** The user obtained BGG API access (previously blocked, see above). This session's n8n MCP tool access had dropped and would not reconnect without a fresh session, so the actual workflow rebuild (pointing everything at Airtable, wiring in BGG for ratings/verification only — icons were kept as the primary visual system, not replaced by BGG box art) was handed to a new Claude Code session with a written brief covering: Airtable base/table/field IDs, the BGG token, the decision to keep icons over BGG cover art, and a pointer to move its working files into this repo's `n8n/` folder for persistence.

**Oct 18 — Credential setup.** Walked the user through creating the two n8n credentials the new session's rebuilt workflows needed (Airtable Personal Access Token, BGG Header Auth). One bug caught and fixed: a credential value copied from a chat message retained markdown backticks, producing a malformed `Authorization` header.

**From here, the other session took over.** The first part of this document ends here; its author did not witness what follows.

## After the handoff (Oct 18–23)

**Oct 18 — Sign-in, Nathan, and a real database.** Google sign-in locks changes to members; "Ask" becomes Ask Nathan, the curator; the site is renamed Board Game Curator. In the evening the data moves a third time, from Airtable to Postgres on the same server (with NocoDB as a spreadsheet view and nightly backups to the private `daddo78/bgc-backups` repo). n8n keeps working unchanged because a database adapter (`at.request`) answers the same calls the Airtable API used to. Late that night, friends get their own shelves, imported from BGG.

**Oct 19 — Faster, watched, shared.** Failure alerts email Dan when a workflow breaks or a backup stalls. Turning the models' "thinking" off cuts Nathan from about 10.7 s to 6.4 s. Friends connect by code, each member's own shelf becomes home, and BGG brings in plays only, never games. Nathan learns facts about any game (catalog, else BGG), "would I like it?" and buy ideas.

**Oct 20 — Profiles, tests, memory.** Wishlists, all-time Top 10s and friends' profile pages; an admin dashboard; rulebook PDFs that Nathan answers from. The first test suite: 31 database checks on every deploy and an 18-question Nathan set, then a nightly self-test on the server. Release notes start (CHANGELOG.md, v0.8–v0.11, posted to the testers' Discord). Late that night Nathan gets a memory: chats saved, lasting notes about each member, and a way to forget them.

**Oct 21 — Rulebooks with page numbers, photos, an admin portal.** Rulebooks are read page by page by a vision model and the PDF is deleted afterwards; Nathan cites "(Rulebook, p. 9)". Photos in the chat ("what does this icon mean?", "what game is this?"). Every member's plays sync nightly. Invites send a welcome email; dashboard, members, Nathan and rulebooks move into one admin portal with exact AI costs from OpenRouter. A background job fills in box art and BGG details for catalog games that had none (455 without art down to 7). Feedback from the cog, emailed to Dan. That evening the plan for Roadmap section 7 is written: move Nathan, then the rest of the small endpoints, off n8n into one small service, starting Oct 25.

**Oct 22 — The service, early.** The prep (a tunnel hostname, the OpenRouter key placed on the server by Dan) was done the same day, so the work started three days ahead of plan. `bgc-api` (TypeScript, Hono on Node, Docker beside Postgres) goes live at `api.ondorilabo.com`: one Google sign-in check for every request using Google's cached public keys, checked inputs, per-member rate limits, and a deploy that starts the new container beside the old one and switches only once it is healthy (43 of 43 health checks answered during a handover). That evening Nathan moves in. His steps are copied word for word from the n8n workflow by a script (`extract-nathan.cjs`), so the two cannot drift apart, and his answer streams to the page as he writes, with Stop and "Ask again". 25 of 25 test questions pass against it; first words about 2.2 s.

**Oct 23, morning — Nathan for everyone.** The new Nathan is switched on for everyone, with n8n kept as a fallback and an off switch until about Nov 6. Understanding the question now starts on just the names at the table (3 ms) while the full shelf loads, and Haiku is routed to Google Vertex first: median first words 2.6 → 2.2 s live, full answers 5.1 → 4.8 s, same cost per question. The 3–5 s outliers were traced to flash-lite being rate-limited on OpenRouter's shared Google quota, with Haiku stepping in (fix noted, not needed yet).

**Oct 23, afternoon — The rest of the site moves.** Every read the page makes, then the everyday changes (stars, shelf edits, friends, wishlists, profiles, Nathan's memory, rulebook edits, player cards, fixed costs), then BGG search, adding a game to your shelf, feedback and Admin's member actions, are ported to the API. Each area sits behind its own switch in Admin (off / admins only / everyone; 14 in all), and Admin's "New API" check asks the API and n8n the same questions with the admin's sign-in and compares the answers before an area goes on. Where the API runs n8n logic (input checks, BGG parsing, email text), that code is copied word for word too. Changes were run against the real database inside transactions that were rolled back. Email moves to Resend's API with a sending-only key Dan placed on the server. Dan switched every area on the same day. Adding to Dan's own collection, photos, imports and rulebook uploads stay in n8n on purpose.

**Oct 23, afternoon — Nathan and kids, and rulebook tidy-ups.** "What should I play with my kids?" had been answered as a one-player question, suggesting a 12+ solo game. It now counts the asker plus the kids, leaves out 13+ games until ages are known, and ends with a question back ("How old are your kids?"). An early version that asked the question-reading model for a "kids" field made it misread a rules question as a recommendation 3 times in 7; detecting kids from the words in code fixed that. Rulebooks gain an "Expansion rulebook" type, only admins may change or remove them, and after reading, a small call names each document from its first two pages ("The Norwegians", "The Edge Cases"), filling only what was left blank.

**Oct 23, evening — Measuring before building.** The plan said to load the page with one combined request. Measuring first showed the page already loads its parts at the same time, so it waits only for the slowest one (the people on a shelf), and a combined request would have shown the games later. The real cause was each person's play history matching plays to games with an OR, which compared every play with every game; rewritten as a plain lookup and then without building the unused games, the same answers came back about 3× faster (Dan's shelf ~355 → ~190 ms; a friend's 844-game shelf 3.9 → 1.2 s). New memory tests found two real misses in Nathan: a stated dislike was saved only about 1 time in 3, and a long "ask a question" instruction added that afternoon made him forget notes. Both were fixed (a code nudge for stated likes, and a short instruction with the two key questions added in code). Sign-in became one click on Google's own account chooser.

## Patterns worth keeping (continued)

- **Copy logic, don't rewrite it, while two systems run side by side.** The API runs n8n's own code (Nathan's steps, input checks, BGG parsing, email text), extracted word for word by a script, so moving a feature can't change its behavior by accident.
- **Move one area at a time behind a switch, and compare first.** Each area of the site has an off / admins / everyone switch, and a check that asks old and new the same questions with a real sign-in before it goes on. Undo is flipping it back.
- **Test changes to live data inside a transaction that's rolled back.** Every new write route and database change was run against the real database this way before going live, and the counts were checked afterwards.
- **Measure before building the planned fix.** The planned "one request" speedup would have made the page feel slower; the measurement pointed at a slow SQL join instead.
- **A longer instruction to a model can quietly break something else.** Adding a "kids" field to one prompt made it misread rules questions; a long "ask a question" rule made Nathan forget notes. A broad test set after each prompt change is what caught both, and moving the logic into code fixed them.
- **Keys and passwords are placed by a person, never pasted through the chat.** The OpenRouter and Resend keys were put on the server by Dan directly. When a key was pasted into the chat, the advice was to treat it as exposed and make a fresh one.

## Patterns worth keeping

- **Never let an LLM emit an identifier (URL, filename, icon name, BGG ID) without validating it against a live, authoritative source before saving.** Both the cover-art agent and the icon-assignment system were built around this after the first naive attempt hallucinated.
- **Pin Docker host ports explicitly.** `ports: - "5678"` in a compose file is not "use the default port" — it's "assign a random one on every restart." This caused the Cloudflare Tunnel outage.
- **A shared Cloudflare Tunnel is tunnel-wide, not per-route.** Don't add a new service's replica to a tunnel that already carries unrelated services unless all replicas can reach all of those services' origins.
- **Before any bulk/destructive-adjacent testing (delete buttons, etc.), assume browser automation can mis-click.** It did, once, here — caught by a row-count audit, not by luck.
